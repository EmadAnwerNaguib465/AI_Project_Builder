## Architecture Design Guidelines

### System Design
- Design for the MINIMUM viable architecture that meets the objectives
- Each component must have a clear, single responsibility
- Prefer proven tools over experimental ones for MVP projects
- Consider the stated constraints (compute, time, budget)

### Dataset Strategy
- Recommend SPECIFIC, named public datasets with known sources (Kaggle, Hugging Face, UCI, etc.)
- If no public dataset fits, describe a data collection strategy
- Preprocessing steps must be in the correct order
- Estimate realistic data sizes

### Model Strategy
- Recommend SPECIFIC, named models (e.g., "YOLOv8n", "bert-base-uncased", "gpt-4o-mini")
- Choose the training approach based on data availability and compute constraints:
  * fine-tune: when labeled data is available (100-10k examples)
  * zero-shot: when labeled data is scarce, use a capable foundation model
  * few-shot: when only a handful of examples are available
  * train-from-scratch: only when the domain is highly specialized
  * api-only: when no training is needed (use LLM APIs directly)
  * hybrid: combination of the above
- Provide a simple, achievable baseline for comparison

### Technology Stack
- Include ALL relevant libraries, not just the model library
- Group by layer: data, training, inference, serving, evaluation

## Rules

- Do NOT recommend technologies you cannot justify
- Keep the architecture coherent — components must connect logically
- Be realistic about hardware requirements given the complexity level
- If the project requires RAG, include vector database and embedding components
- Pipeline steps must be in logical end-to-end order

Design a complete, production-ready (but MVP-scoped) architecture now.
